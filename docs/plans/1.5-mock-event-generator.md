### 0A. Premise

- **Real problem:** every visual feature from Phase 2 to Phase 7 must be testable before live data exists (`docs/PLAN.md:21`). Without a mock stream, Phases 2-3 have nothing to render and 7.1 stuck rules have nothing to trip.

- **Do-nothing cost:** 1.6 cannot build `MockSource`; every later e2e test hand-writes events.
- **Direct or proxy:** direct. The proxy risk is a stream that passes "has every event type" but is not causally valid (ends before starts, orphan subagents). The written Test line does not check validity.

## Accepted scope (working plan, implementation still pending design in the review sections)

1. `src/data/mock.ts`: seeded PRNG (hand-written, no dependency); a fixed scripted spine that always holds, for every seed: 1 project, 3 sessions across both providers, root agents plus 8 subagents, tool calls, tool errors, hand-offs (delegate and return), a task queue with dequeue, every one of the 13 event types; one stuck agent silent longer than 5 min while not done; one agent in `needs_attention`, silent longer than 5 min while it is open, then `attention_cleared` (R2-3b, D11); at least one subagent spawn and one subagent `agent_end` per provider (R2-2, D8); one tool call open longer than 2 s and one agent ending `ok` (R2-1, D9); one agent repeating the same tool + `argsHash` 5 times; one with 3 tool errors in a row; one slow tool call; each of these three is followed by a clearing step: a different `ok` call, an `ok` call, the slow call's `tool_call_end` (R2-3a, D10). The seed varies only the filler (names, models, tool choices, token counts, jitter). Time scaling supported (owner and form decided in Section 1).
2. Options `{ agents, durationMs }` (names final in Section 1) beyond the fixed scenario, with lazy `Iterable<Event>` output.
3. Exported `checkStream(events)`, as approved in E1 (D2): every event passes `parseEvent`; ts non-decreasing; event ids unique; tool calls paired; subagent spawn after its parent; nothing after `session_end`; attention cleared or still open.      active/in_tool/waiting --(wrap-up, S1-4)--> ended (agent_end)

```
  Prevented by: one script per agent, built in order; checkStream asserts each (E1).
```

## Section 4 — Data flow and edge cases
