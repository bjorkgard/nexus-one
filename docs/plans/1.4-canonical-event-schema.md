## Step 0 record

### 0A. Premise

- **Real problem:** every later phase passes the same events between three producers (mock 1.5, Claude adapter 4.1, Codex adapter 4.2) and many consumers (store, sim, UI). Without one runtime-checked contract, each producer invents its own shapes and the client trusts whatever the WebSocket sends.
- **Target outcome:** one file, `src/shared/schema.ts`, that both Node (collector) and the browser import; types come from the zod schemas (`z.infer`), so there is no second declaration to drift.
- **Do-nothing cost:** 1.5 and 1.6 cannot start; 4.x adapters would define shapes ad hoc.
- **Direct or proxy:** direct. The plan names the right artifact.
- **Gaps in the task as written (findings, pending, not accepted changes):**
  - G1. No common envelope. The test mentions "missing id", but `id`, timestamp, and which session/agent an event belongs to are not specified.
  - G2. Queue has no exit. `task_queued` exists, but 4.15 tests "dequeue 2, 3 trays" and no event removes a task.
  - G3. Entity fields missing for consumers: `Agent.model` and a display name (5.4, cost in 4.3); `Session.projectId`, `provider`, start/end times; `Project` fields at all.
  - G4. `tool_call_start`/`tool_call_end` have no pairing id; 4.3 "same tool call repeated N times" and 4.8 "open tool call longer than 2 s" need one.
  - G5. `message` text has no size limit. Transcript text crosses the WebSocket (TODOS.md P1 "Lock down the collector WebSocket") and UI shows only 60 chars (4.12).
  - G6. `stage` enum values live in 4.8, not in 1.4. The schema must own them or 4.8 becomes a second declaration.
  - G7. "grep finds no duplicates" is a manual check; nothing keeps it true after 1.4.
  - G8. Unknown-key policy is unstated (reject, strip or pass). Adapter versions (4.1) and forward compatibility depend on it.
  - G9. How a session's main agent appears is unstated (its own `agent_spawn` with `parentId: null`, or implied by `session_start`).
  - G10. `handoff` direction and `needs_attention` reason are unstated (4.14, 4.3).
