### Units and coordinates

- 1 world unit = 1 m. +Y is up. Camera sits in the (+x, +y, +z) octant: `isoDirection()` = (−1, −1, −1)/√3. Then the camera's right axis is (1, 0, −1)/√2, so +x projects right of the origin (`e2e/smoke.spec.ts:89-97` holds) and elevation is asin(1/√3) = 35.264°. Ground is the plane y = 0. Campus ground centre is the world origin `(0,0,0)`. The camera looks at the centre of the _framing bounds_ (design Q1): the bounds of what is built, which in 2.1 is the slab only (x,z ∈ [−60,60), y ∈ [−1.4,0]); once floors exist the framing bounds grow to the campus box. (Supersedes D9's "campus box centre" target point; the D9 smoke-test and `getCamera().target` contract stand.); `e2e/smoke.spec.ts` "project maps origin to canvas center" becomes "camera target maps to canvas center" using the new `getCamera().target`.
- `DEFAULT_FLOORS = 6` (exported from `zones.ts`) until 2.5 derives the count; Stage, overlay and e2e all read it.
- `FLOOR_HEIGHT = 4` m. Floor index `f` spans `y ∈ [f·4, (f+1)·4)`. `floors` counts every occupied level including the lobby (D10): lobby is floor 0, offices are floor 1..T with T = floors − 1, roof is floor `floors`.
- Boxes are half-open: `min` inclusive, `max` exclusive on every axis, so stacked floors and side-by-side zones never both contain a shared face.

### Zone registry (R2, R3)

```ts
type ZoneKind = "site" | "floor" | "room";   // approved D2 shape; no other kinds
interface Zone {
  id: string;            // stable slug: "campus", "lobby", "garage", "loading-bay", "floor-3", "break-room", "server-room", "roof"
  name: string;          // display: "Floor 3"
  kind: ZoneKind;
  floor: number;         // 0 = ground/lobby; offices 1..floors−1; roof = floors; campus (site) = 0
  parentId: string | null;
  box: { min: Vec3; max: Vec3 };
}
createZoneRegistry({ floors }): {
  zones: readonly Zone[];
  byId(id): Zone | undefined;
  at(point: Vec3): Zone | undefined;   // deepest containing zone
}
```

Tree:

```
campus (site, floor 0, box spans y 0..roof top)
├── lobby        (floor, floor 0, tower footprint)
├── garage       (floor, floor 0, beside tower)
├── loading-bay  (floor, floor 0, beside tower, not touching garage)
├── floor-1..T   (floor, floor k, tower footprint; T = floors − 1)
│   ├── break-room   (room, always inside floor-1; D11)
│   └── server-room  (room, inside floor T)
└── roof         (floor, floor `floors`, tower footprint)
```

Growth contract (D11): zone ids never change. Adding a floor (2.5) moves only `server-room` and `roof` boxes and grows `campus`; 2.5 rebuilds the registry and everything built from it (geometry, nav graph). Break room never moves.

Footprints live in one `FOOTPRINTS` table in `zones.ts`; 2.3/2.4/2.7 refine them. Starting values (x/z in metres, centre at origin):

| Zone                 | x range    | z range   | y range               |
| -------------------- | ---------- | --------- | --------------------- |
| campus               | [-60, 60)  | [-60, 60) | [0, (floors + 1)·4)   |
| lobby, floor-k, roof | [-15, 15)  | [-15, 15) | floor band            |
| garage               | [20, 50)   | [-30, 10) | [0, 4)                |
| loading-bay          | [-50, -25) | [-20, 5)  | [0, 4)                |
| break-room           | [-13, -3)  | [5, 13)   | floor band of floor 1 |
| server-room          | [3, 13)    | [-13, -5) | floor band of floor T |

With `floors = 2` (T = 1) both rooms sit in floor-1 and do not overlap (opposite corners).

Rules checked by `validateZones` (throws `ZoneError` naming both ids):

1. Unique ids; every `parentId` exists; no cycles.
2. `min < max` on every axis; all numbers finite.
3. Child box lies inside parent box (closed containment).
4. Every floor/room zone's box y range lies inside its floor band `[floor·4, (floor+1)·4)`, so a wrong `floor` index is caught.
5. Siblings do not overlap at all (half-open intersection has positive volume); with rule 4 this covers "no overlap within a floor". The site zone has no siblings.
   `createZoneRegistry` checks its input first: `floors` must be an integer in `[2, 40]` (lobby + at least one office floor), otherwise `RangeError` (not a `ZoneError`).

`createZoneRegistry` calls `validateZones` before returning, so a bad table fails at startup and in tests, never silently. It then deep-freezes every zone, box, `min` and `max`, and the `Zone` type is readonly all the way down, so validation stays true for every consumer (eng D2).

`at(point)`: non-finite coordinate → `TypeError` (same rule as `projectToPage`); outside campus → `undefined`; else deepest zone whose half-open box contains the point.
